What I learned

Describe your design: hypervisors, tenants, VNIs and addresses. Which tenants overlap, and why did you place each VM where you did?

For this lab I use three hypervisors, hv1, hv2, and hv3. I have two tenants, alpha and beta, each with its own VNI (110 for alpha and 220 for beta). Both tenants use the same network address range of 10.61.20.0/24, but are kept apart by their respective VNIs. I placed the VMs of tenant alpha across all three hypervisors which alpha1 on hv1, alpha2 on hv2, and alpha3 on hv3 to ensure redundancy and load distribution. For tenant beta, I placed beta1 on hv2 and beta2 on hv3 to demonstrate that tenants can share hypervisors while still maintaining isolation through VNIs.

Two of your VMs have the same IP address. Using your evidence, explain how a ping reaches the right one â€” and what would have to go wrong for one tenant to see another's traffic.

Since both VMs have the same IP address, the ping would reach the one that is currently active and has a valid MAC address associated with that IP in the ARP table. For one tenant to see another's traffic, there would have to be a misconfiguration in the VXLAN encapsulation or a failure in the VNI-based isolation, allowing packets to be forwarded between tenants.

Using your evidence, explain what was flooded, to which hypervisors, and what each VTEP learned. With 50 hypervisors in one VNI, how many copies would one broadcast need â€” and how would EVPN change that?

The broadcast would be flooded to all hypervisors in the same VNI. Each VTEP would learn the MAC addresses of the VMs connected to it. With 50 hypervisors in one VNI, one broadcast would need 50 copies, one for each hypervisor. EVPN would change that by using a control plane to distribute MAC address information, reducing the need for flooding and allowing for more efficient traffic forwarding.

Compare your two MTU fixes using your measurements. Which would you choose for a data centre, what does each cost, and who has to change what?

I would choose the second MTU fix with an underlay MTU of 9000 and tenant MTUs of 1500. This allows for larger packets to be sent across the underlay network, reducing fragmentation and improving performance. The cost of this fix is that all hypervisors and tenants must support the larger MTU, which may require configuration changes on the network devices and VMs. The first fix with an underlay MTU of 1500 and tenant MTUs of 1450 would limit packet sizes and could lead to fragmentation, which can degrade performance.

If your hypervisors' VTEPs were P4 switches running the lecture's vtep.p4, what would have to fill the vtep_encap table, and how? What would replace flood-and-learn?

The vtep_encap table would need to be populated with the MAC addresses and corresponding VNI information for each VM. This could be done through a control plane protocol or manual configuration. EVPN would replace flood-and-learn by providing a more efficient way to distribute MAC address information across the network.
